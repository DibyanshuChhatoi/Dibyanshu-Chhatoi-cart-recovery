# Original YottaFlex AI Submission Guidelines and FAQ

## Candidate Project — Submission Guidelines

Show us how you think, build, validate, and work with AI.

**Your challenge window:** 72 hours. Your submission window is 72 hours. Artifact timestamps will be used to verify the window.

1. **Make it run:** Submit working, executable code. Include clear steps so another person can install dependencies, configure the project, run it, and verify key behavior.
2. **Show your work:** Use a public GitHub repository. Make the evolution of your work understandable through the code, meaningful commits, and supporting context.
3. **Use LLMs transparently:** LLM tools are allowed. Submit your prompt history and explain where AI accelerated your work, where you relied heavily on it, and what you personally reviewed, changed, or validated.
4. **Make your reasoning visible:** Help reviewers understand the problem, assumptions, key decisions, trade-offs, testing approach, limitations, and how you know the solution works.

Be ready to walk us through your solution. We value sound judgment, working software, honest AI disclosure, and clear communication.

## Candidate Project FAQ

1. **When does my 72-hour window start?** When YottaFlex AI sends you the project. Your deadline is exactly 72 hours later, using the recorded send timestamp and its time zone.
2. **Can I submit early?** Yes. Submit as soon as ready. Keep the public repository available and editable until the 72-hour deadline; the latest version at the deadline is evaluated.
3. **How do I submit my repository link?** Create a new, dedicated public GitHub repository. Send the link from the same email address used during recruitment and follow the portal instructions.
4. **What belongs in my repository?** Include your code, prompt history, and relevant supporting artifacts in a clearly identifiable directory. There is no fixed list of documents or prescribed format.
5. **Which AI tools may I use?** Any LLM or AI coding tool is allowed, including cloud-based and locally hosted tools. AI use is unrestricted; judgment, understanding, ownership and validation matter.
6. **What prompt history is required?** Include all prompts submitted to every AI tool used. AI responses are optional. If a tool cannot export prompts, keep a reasonable record and disclose the limitation.
7. **Must I write all code myself?** The project must be individual work. AI and public learning resources are allowed; implementation help from other people is not. Understand core logic, design choices, dependencies and limitations.
8. **Can I choose my own technology stack?** Yes. Choose suitable languages, frameworks and storage. Use only free or locally runnable services, and avoid unusually large or slow dependencies where possible.
9. **Must I provide a live demo or automated tests?** No hosted demo or automated test suite is mandatory. Provide clear setup/run instructions and demonstrate how you verified core functionality. Document environment needs and limitations.
10. **Can I reuse existing code?** Standard dependencies and small illustrative snippets are acceptable. Do not import a complete solution or existing code that performs the core project work. Follow licenses and provide attribution where required.
11. **What if requirements are unclear or work is incomplete?** Make reasonable assumptions and explain them. Partial solutions are acceptable if you state what works, what remains incomplete, known limitations and next steps. Explain requirement deviations.
12. **What must I keep out of a public repository?** Never include secrets, credentials, personal or sensitive information, or proprietary code you are not authorized to publish. Use safe sample data and local configuration; explain setup in the README.
